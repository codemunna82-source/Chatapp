# VOXO Android Build & Release

This is the Phase 11 companion to `README.md`: how to go from this
checkout to a real, installable APK — a debug smoke build, and a
genuinely production-signed release build. See `ARCHITECTURE.md` §8 at
the repo root for the design rationale behind everything here.

## What's committed vs. what you provide

The native `android/` project generated by `expo prebuild` **is committed**
to this repo, so the release-signing configuration is version-controlled
and reproducible without depending on Expo's cloud (EAS) — you can build
locally with plain Gradle if you prefer.

**Never committed, and never fabricated by any tooling in this repo:**
- A production keystore (`.keystore`/`.jks` file)
- `android/app/keystore.properties` (the real passwords/alias file —
  `keystore.properties.example` is the committed template)

Every release build in a fresh checkout falls back to **debug signing**
until you provide a real keystore. `android/app/build.gradle` prints a loud
warning when this fallback is in effect — if you don't see that warning,
you're signing with your own real keystore.

## Prerequisites (your machine, not this environment)

This sandbox's network policy blocks `dl.google.com` (Android's SDK/Maven
repository), so **no Gradle build could be executed or verified in this
session** — not the debug build, not the release build. Everything below
is genuinely correct configuration (verified by `expo prebuild` succeeding
and the generated files being reviewed), but the actual `./gradlew`
invocation needs to happen on a machine with real access to Google's Maven
repo and the Android SDK:

- **Android Studio** (simplest way to get the SDK, platform-tools, and an
  emulator) — https://developer.android.com/studio
- Or the **command-line SDK tools** alone if you don't want the IDE:
  https://developer.android.com/studio#command-tools, then:
  ```bash
  sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"
  ```
- **JDK 17+** (Node/Gradle need this; Android Studio bundles one)
- Node.js 20+, and `cd mobile && npm install` already run

## 1. Debug smoke build (fastest way to get an installable APK)

```bash
cd mobile
npx expo prebuild --platform android   # only if you've changed app.config.ts
                                        # since android/ was last generated —
                                        # otherwise skip, android/ is already committed
cd android
./gradlew assembleDebug
```

Output: `android/app/build/outputs/apk/debug/app-debug.apk` — installable
on a device/emulator with `adb install`, signed with the well-known Android
debug key (fine for testing, **never for distribution**).

## 2. Producing a real release keystore

```bash
cd mobile/android/app
keytool -genkeypair -v \
  -storetype PKCS12 \
  -keystore voxo-release.keystore \
  -alias voxo-release \
  -keyalg RSA -keysize 2048 -validity 10000
```

`keytool` will prompt for a store password, a key password, and your
organization's details (CN/OU/O/L/ST/C — these go into the certificate,
not into VOXO itself). **Store the resulting `.keystore` file and both
passwords somewhere durable and secret** — Google Play requires the *same*
signing key for every future update to this app; losing it means you can
never update a previously-published `com.voxo.app` again.

Then:

```bash
cp keystore.properties.example keystore.properties
# edit keystore.properties: storeFile=voxo-release.keystore, and your two
# real passwords + the alias you chose above (voxo-release, if you used
# the example as-is)
```

`keystore.properties` is gitignored — verify with `git status` that it
never shows up as a change to commit.

## 3. Real release build

```bash
cd mobile/android
./gradlew assembleRelease
```

With `keystore.properties` present, `build.gradle` uses your real signing
config automatically — check the Gradle output for the `[VOXO] ... DEBUG
keystore` warning; **its absence confirms real signing is active**.

Output: `android/app/build/outputs/apk/release/app-release.apk` — this is
the genuinely production-signed `VOXO-release.apk`. Rename it however you
like; the file itself is what matters.

To build an Android App Bundle instead (required for a new Play Store
submission):

```bash
./gradlew bundleRelease
# android/app/build/outputs/bundle/release/app-release.aab
```

## Before every release build

- Bump `ANDROID_VERSION_CODE` in `mobile/app.config.ts` (it must increase
  on every build you intend to distribute — Android enforces this) and the
  `version` field alongside it.
- Run the full check suite: `npm run typecheck && npm run lint && npx expo
  export --platform android`.
- If `app.config.ts` changed since the last `expo prebuild`, re-run it
  (`npx expo prebuild --platform android --clean`) so `android/` reflects
  the current config before building.

## Alternative: EAS Build (Expo's cloud build service)

If you'd rather not install the Android SDK locally, EAS Build compiles on
Expo's infrastructure and hands you a downloadable APK/AAB — it still uses
the exact `android/` project and signing setup described above (EAS can
also manage the release keystore for you, if you prefer not to hold it
yourself):

```bash
npm install -g eas-cli
eas login
eas build --platform android --profile production
```

This requires an Expo account and networks this sandbox doesn't have
access to either (`cdp.expo.dev` was rejected by this environment's
network policy during Phase 11), so it's untested here for the same
reason the local Gradle build is — but it needs no local Android SDK,
which makes it the more likely first thing to actually try.
